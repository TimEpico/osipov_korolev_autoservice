# AutoService — журнал технического обслуживания автомобиля

Учебный проект Осипова и Королёва.

[Открыть веб-прототип](https://timepico.github.io/autoservice-mobile-preview/)

Проект включает веб-журнал, сервер push и консольную программу C++. C++-модуль использует собственные демонстрационные данные. Обмен данными между ним и веб-приложением пока отсутствует.

## 1. Паспорт проекта

### Название проекта
AutoService — журнал технического обслуживания автомобиля.

### Цель проекта
Помочь водителю учитывать пробег, хранить историю обслуживания и своевременно планировать следующее ТО.

### Целевая аудитория
Владельцы одного или нескольких автомобилей, обслуживающие машину самостоятельно или в автосервисе.

### Главный функционал
1. Добавление автомобилей и обновление пробега.
2. Планирование работ, запись замен масла и деталей, история обслуживания.
3. Напоминания по дате и пробегу, включая системные push-уведомления.

Учебный модуль C++ дополнительно обеспечивает массивы автомобилей и пользователей, вывод списков, выбор по ID и поиск по характеристикам.

### Какую проблему решает продукт и как
Водителю трудно помнить даты и пробег всех замен. Чеки и отдельные заметки могут потеряться, поэтому очередное обслуживание можно пропустить.

AutoService связывает работы с конкретной машиной. Водитель указывает срок следующего ТО и запас для предупреждения. Приложение показывает предстоящие работы и напоминает о сроке. После обслуживания пользователь вводит фактические дату и пробег, а запись появляется в истории.

### Чем продукт лучше другого продукта на рынке
Предлагаемое преимущество AutoService для выбранной аудитории — короткий путь от выбора автомобиля до записи о ТО. Пробег, планы и история доступны из карточки машины. Запуск по ссылке и добавление на экран «Домой» упрощают первый доступ. Напоминание можно задать одновременно по дате и километражу.

Это проектная гипотеза. Сравнительные испытания с конкретными рыночными продуктами пока не проводились. Преимущество предстоит проверить по времени добавления машины, записи о работе и настройки напоминания.

### MVP и планируемый результат
MVP объединяет автомобили и пробег, задачи и историю, напоминания о ТО. Результат — работающий веб-прототип и запускаемая программа C++ для демонстрации массивов.

### Ограничения
- Пробег вводится вручную.
- Журнал сохраняется в браузере устройства. Очистка данных сайта может удалить записи.
- Регистрация и синхронизация журнала между устройствами пока отсутствуют.
- Массивы C++ фиксированы: три машины и два пользователя. Добавление через консоль и сохранение в файл пока отсутствуют.
- Табельный номер — дополнительный идентификатор пользователя для учебного задания.
- Поиск находит подстроку с учётом регистра.
- Календарное push-напоминание планируется на 09:00 в часовом поясе устройства в день ТО минус запас дней. Пробеговое отправляется после обновления показаний.
- Фоновая доставка требует разрешения пользователя, поддерживаемого браузера и сети.

## 2. Три сценария работы продукта

### Сценарий 1. Добавить автомобиль и обновить пробег
Участник — автовладелец.
1. Открывает веб-приложение и нажимает «+ Автомобиль».
2. Вводит марку, модель и текущий пробег.
3. Сохраняет автомобиль и выбирает его в списке.
4. Позже нажимает «Обновить пробег» и вводит новое показание.

Результат — карточка показывает актуальный пробег и дату обновления. Запись сохраняется в браузере.

### Сценарий 2. Получить напоминание и записать выполненное ТО
Участник — автовладелец.
1. При пробеге 59 000 км создаёт задачу «Замена масла» на 60 000 км.
2. Указывает запас предупреждения 500 км.
3. Включает уведомления и разрешает их в браузере.
4. Обновляет пробег до 59 500 км. Появляется напоминание и запрос на отправку push.
5. После посещения сервиса открывает задачу, указывает фактические дату и пробег, нажимает «Выполнено».
6. Открывает «Историю».

Результат — работа видна в истории. После успешной синхронизации выполненная работа исключается из серверного расписания.

### Сценарий 3. Найти машину и владельца в программе C++
Участник — пользователь учебного модуля.
1. Запускает программу и выбирает пункт 1 для вывода массива автомобилей.
2. Выбирает пункт 5, вводит Corolla и получает Toyota Corolla с ID владельца 1.
3. Выбирает пункт 4 и вводит ID 1. Программа показывает Ивана Петрова, табельный номер AS001.
4. Выбирает пункт 6 и вводит AS002. Программа находит Анну Смирнову.

Результат — найдены нужные записи. При отсутствии совпадений выводится «Запись не найдена».

## 3. Массивы на C++

Главный элемент продукта — автомобиль, для которого ведётся учёт пробега и срока ТО.

[Исходный код C++](modules/cpp/main.cpp)

| Массив | Тип | Поля |
|---|---|---|
| cars | std::array<Car, 3> | id, name, plate, mileage, nextService, ownerId |
| users | std::array<User, 2> | id, name, personnelNumber |

Поле ownerId связывает автомобиль с id пользователя. ID является идентификатором записи, а индекс — её позицией в массиве.

| Пункт меню | Действие |
|---|---|
| 1 | Вывод полного массива автомобилей |
| 2 | Вывод полного массива пользователей |
| 3 | Выбор автомобиля по точному ID |
| 4 | Выбор пользователя по точному ID |
| 5 | Поиск по части названия автомобиля или госномера |
| 6 | Поиск по части имени или табельного номера |
| 0 | Выход |

Поиск перебирает массив и выводит все совпадения. Выбор по ID использует точное числовое сравнение. Программа обрабатывает пустой запрос, неправильный ID и неизвестный пункт меню. Для машины рассчитывает остаток пробега до ТО.

## 5. Запуск C++

Требуется компилятор с поддержкой C++17, например Clang или GCC. Из корня репозитория на macOS/Linux выполните:

    mkdir -p build
    c++ -std=c++17 -Wall -Wextra -pedantic modules/cpp/main.cpp -o build/autoservice
    ./build/autoservice

На Windows с установленным MinGW g++ из PowerShell:

    New-Item -ItemType Directory -Force build
    g++ -std=c++17 -Wall -Wextra -pedantic modules/cpp/main.cpp -o build/autoservice.exe
    .\build\autoservice.exe

Для автоматической проверки на macOS/Linux нужен Python 3:

    python3 tests/check_cpp.py

Проверены оба полных массива, выбор записей по ID, поиск по четырём характеристикам, отсутствие совпадений, неправильный ID, пустой ввод, неверный пункт меню, расчёт ТО и конец ввода. Ожидаемый результат — «Все 16 проверок C++ пройдены».

Сборка и проверки выполнены на macOS с Clang. Запуск на Windows ещё предстоит проверить.

## 6. Веб-приложение и push

[Открыть опубликованную версию](https://timepico.github.io/autoservice-mobile-preview/)

Для локального просмотра из корня проекта:

    python3 -m http.server 8000 --directory modules/web

Откройте http://localhost:8000. Для остановки сервера нажмите Ctrl+C. Локально доступны интерфейс и журнал. Опубликованный сервер push допускает запросы от GitHub Pages; для другого источника требуется изменить его настройку.

На iPhone/iPad для push требуется iOS/iPadOS 16.4+, добавление приложения на экран «Домой» и разрешение уведомлений. В разделе «Push-уведомления» доступна кнопка «Тест через 10 секунд».

### Схема доставки
1. Браузер создаёт подписку после разрешения пользователя.
2. push.js отправляет подписку и расписание в Cloudflare.
3. Durable Object хранит состояние устройства и ставит будильник.
4. Worker шифрует сообщение и отправляет его push-службе браузера.
5. sw.js показывает уведомление; нажатие открывает задачу.

Полный журнал хранится на устройстве. Сервер получает подписку, подписи работ, идентификаторы и сроки. Закрытый ключ отправителя хранится в Cloudflare Secrets и исключён из репозитория.

Проверка серверного модуля:

    cd modules/notifications
    npm ci
    node check.mjs

Для собственного развёртывания нужны Cloudflare, Wrangler и секреты VAPID_PUBLIC и VAPID_PRIVATE. При смене сервера следует согласованно заменить адрес и открытый ключ в push.js. Файл .dev.vars с локальными секретами исключён через .gitignore.
